# content-topic-research-web

네이버 검색·NAVER 검색어트렌드·Google Trends·Search Console·뉴스·커뮤니티·공식자료에서 얻은 신호를 한곳에 모아, **검색량이 아니라 게시 가치**를 기준으로 콘텐츠 주제를 선별하는 Next.js 도구입니다.

## 핵심 원칙

- 네이버 검색 API: 키워드 생산기가 아니라 **사용자가 실제로 묻는 문제 탐지기**로 사용
- NAVER 검색어트렌드 / Google Trends: WHAT보다 **WHEN(수요·발행 시기)** 판단에 사용
- 네이버 뉴스: 기사 재작성보다 **변경 감지**에 사용
- Search Console: 내 사이트가 이미 노출되는 **실제 기회**를 우선 발견
- 카페·지식iN·커뮤니티: 사실 근거가 아니라 **불편·질문 표현** 탐색
- 공식기관·제조사 자료: **사실 검증**에 사용
- 같은 검색 의도는 한 페이지로 클러스터링
- 웹서핑한 내용을 직접 체험한 것처럼 쓰지 않음
- 60점 미만 후보는 자동으로 “제작 보류” 상태로 판단

## 실행

## NAVER API HUB 설정

이 프로젝트는 2026년 NAVER API HUB 기준으로 다음 Application API를 사용합니다.

- 검색어트렌드
- 뉴스
- 블로그
- 지식iN
- 카페
- 웹문서

NAVER Cloud Platform의 **NAVER API HUB > Application > 인증 정보**에서 Client ID와 Client Secret을 확인한 뒤 프로젝트 루트에 `.env.local`을 만듭니다.

```env
NAVER_API_HUB_CLIENT_ID=...
NAVER_API_HUB_CLIENT_SECRET=...
```

기존 NAVER Developers의 `X-Naver-Client-Id` / `X-Naver-Client-Secret` 방식이 아니라 NAVER API HUB의 다음 인증 헤더와 엔드포인트를 사용합니다.

- API 도메인: `https://naverapihub.apigw.ntruss.com`
- Client ID 헤더: `X-NCP-APIGW-API-KEY-ID`
- Client Secret 헤더: `X-NCP-APIGW-API-KEY`
- 검색: `/search/v1/*`
- 검색어트렌드: `/search-trend/v1/search`

> Client ID와 Client Secret은 브라우저 코드에 넣지 않습니다. Next.js Route Handler에서만 읽도록 구성되어 있습니다.

## NAVER 검색어트렌드 사용 방식

앱에서 최대 5개 키워드를 비교할 수 있습니다. API가 반환하는 `ratio` 값은 절대 검색량이 아니라 요청한 기간·검색어 집합 안에서 정규화된 상대 지수이므로, **주제 결정용 절대 검색량이 아니라 수요·계절성·발행 시기 신호**로만 사용합니다.

- 최근 90일: 주간 단위
- 최근 1년: 월간 단위
- 저장 시 최근 4개 구간의 평균 상대지수를 `trendScore`로 기록

## 데이터 보관

현재 버전은 개인용 리서치 도구를 전제로 브라우저 `localStorage`에 신호와 후보를 저장합니다. 서버 DB가 필요하면 Supabase/Firebase/Postgres 등으로 저장 레이어만 교체할 수 있습니다.

- Position / 게재순위 / 평균 게재순위

## 원클릭 자동 탐색

첫 화면의 **오늘의 자동 탐색 시작** 버튼은 키워드 입력 없이 동작합니다.

- 현재 월/계절과 서비스 기본 방향(생활 문제 해결 기록소 · 디지털 생활 도구)을 기준으로 매일 5개의 시드 주제를 자동 선택합니다.
- NAVER 지식iN, 카페, 블로그에서 실제 불편과 질문 표현을 찾습니다.
- NAVER 뉴스는 변경 감지용으로 조회합니다.
- NAVER 웹문서에서는 공식 기관·제조사 도메인을 우선 식별해 근거 후보로 저장합니다.
- NAVER 검색어트렌드는 최근 90일 상대 검색지수로 수요와 발행 시기를 보조 평가합니다.
- 수집한 신호를 주제별로 묶어 Candidate와 품질 점수를 자동 생성합니다.
- 직접 경험 자료가 없는 후보는 조사·검증형 또는 비교·분석형으로 생성하며, 직접 체험한 것처럼 서술하지 않도록 프롬프트에 명시합니다.

한 번 탐색한 뒤 **다른 주제 5개 찾기**를 누르면 날짜 기반 시드 풀을 회전해 다음 후보군을 조사합니다. 수동 검색 UI는 자동 탐색에서 빠진 주제를 추가 조사할 때만 사용하면 됩니다.

## 자동 판단 중심 사용 흐름

현재 UI는 수동 선택을 최소화하도록 구성합니다.

1. `오늘의 자동 탐색 시작`을 실행합니다.
2. `주제 후보`는 게시 가치 점수 내림차순으로 자동 정렬됩니다.
3. 후보 상세 화면에서는 점수·감점·콘텐츠 방식·고유 결과물을 앱이 먼저 판단한 결과로 보여줍니다.
4. 일반 사용자는 슬라이더나 체크박스를 조정할 필요가 없습니다. 직접 수정이 필요한 경우에만 `고급 설정`을 펼칩니다.
5. 주제 후보 카드를 누르면 해당 후보가 선택되는 동시에 ChatGPT용 프롬프트가 클립보드에 바로 복사됩니다.
6. 후보 상세 화면의 `ChatGPT 프롬프트 다시 복사` 버튼으로 언제든 다시 복사할 수 있습니다.

생성되는 프롬프트는 ChatGPT가 후보를 그대로 받아쓰지 않고 게시 가치부터 다시 판단하도록 설계되어 있습니다. 웹 검색을 사용할 수 있는 환경에서는 최신 1차 자료를 직접 확인하고, 콘텐츠 방식·대상 독자·목차·고유 결과물도 모델이 최종 선택하도록 지시합니다. 게시 가치가 충분한 경우에는 WordPress용 완성 원고와 함께 **대표 이미지 생성 프롬프트**와 **Rank Math SEO 패키지(포커스 키워드, SEO title, 영문 퍼머링크, SEO description, 태그, 카테고리)**도 별도로 생성합니다. Rank Math는 본문 규격을 강제하는 용도가 아니라 메타데이터 입력 보조용으로만 사용합니다.

AdSense 승인을 보장하는 도구는 아닙니다. 대신 Google이 안내하는 고유하고 유용한 콘텐츠 방향에 맞춰 뉴스 재작성, 가상 체험담, 대량 템플릿, 공식 근거가 약한 글을 게시하지 않는 품질 게이트로 사용하는 것이 목적입니다.

## 2026-08 콘텐츠 품질 원칙

- 앱의 홈 카드(로고)를 누르면 작업 내용을 모두 초기화하고 `/`로 이동합니다. 입력값·리서치 신호·주제 후보가 있으면 브라우저 기본 확인창으로 작업 손실 가능성을 먼저 안내합니다.
- `오늘의 자동 탐색 시작`이 끝나면 자동으로 `주제 후보` 화면으로 이동하고 페이지 최상단으로 스크롤합니다. 별도의 “후보 보기” 버튼을 거치지 않습니다.
- 대시보드 통계 카드는 모바일에서도 2열로 표시합니다.
- ChatGPT 출력은 `auto-publisher-web`의 표준 Markdown 규격(`# 1. 게시용 본문` ~ `# 4. Rank Math SEO 패키지`)을 사용합니다. 게시용 본문은 `<!-- 게시용 본문 시작 -->` / `<!-- 게시용 본문 끝 -->` 사이에 두고, 첫 H1은 Auto Publisher가 제목으로 추출한 뒤 실제 WordPress 본문에서는 제거합니다.

콘텐츠는 **형식을 일부 통일하되 사고방식까지 통일하지 않는 것**을 원칙으로 합니다. 동일한 서론·FAQ·결론·안전문구를 제목만 바꿔 반복하지 않고, 문제별로 실제로 필요한 판단 순서와 검증 경로를 새로 설계합니다.

사이트 콘셉트는 `생활 문제 해결 기록소 + 디지털 생활 도구`입니다. 직접 경험 자료가 있으면 사진·스크린샷·사용 기간·비용·작업 시간·실패 사례 같은 증거를 우선 활용하고, 직접 경험이 없으면 체험담을 만들지 않습니다. 대신 제조사·공공기관 공식 문서 교차 비교, 조건별 결정표, 화면 경로 비교, 공개 사용자 사례의 반복 혼동 지점 분석처럼 **조사 자체를 고유 결과물**로 만듭니다.

발행 전에는 한국어 조사 오류, 중복 단어, 자동 조합형 문장, 다른 글에도 그대로 붙일 수 있는 공통 문단, 근거 없는 전문가·검수 표현, 충돌하는 날짜를 전수 점검하도록 프롬프트에 강제합니다.


## Auto Publisher 연동 규칙

ChatGPT 최종 결과의 **전달 규격은 고정**하지만 실제 게시 본문을 템플릿화하지 않습니다.

- 고정되는 것: `# 1. 게시용 본문`, `# 2. 게시 전 확인 자료`, `# 3. 대표 이미지 생성 프롬프트`, `# 4. Rank Math SEO 패키지`, 본문 시작/끝 주석, Rank Math 필드명
- 자유롭게 달라져야 하는 것: 문제 정의, 판단 순서, H2/H3 구성, 비교표/체크리스트/FAQ 사용 여부, 결론 방식, 문장 리듬
- 모든 글에 `서론 → 원인 → 해결법 → FAQ → 결론` 같은 공통 구조를 강제하지 않습니다.
- 최종 원고 전에 주제별 “이 글만의 판단 흐름”을 점검하도록 프롬프트에 명시합니다.
- 출력 전체를 복사해 `auto-publisher-web`에 붙여넣으면 제목·본문·대표 이미지 ALT·Rank Math 메타데이터가 기존 파서 규격으로 추출되도록 맞춥니다.

즉, **컨테이너는 표준화하고 콘텐츠의 사고방식은 표준화하지 않는 것**이 원칙입니다.

## 고정 카테고리 정책

자동 발행에서 띄어쓰기나 표현 차이로 WordPress 카테고리가 계속 늘어나는 것을 막기 위해 최종 ChatGPT 출력의 `카테고리명`은 다음 5개 중 하나만 사용합니다.

- 집 관리
- 디지털 생활
- 생활 행정
- 정리·보관
- 제품 사용

계절, 브랜드, 제품명, 세부 증상은 카테고리를 새로 만들지 않고 태그로 표현합니다. 글의 전달 포맷과 taxonomy는 고정하지만 실제 게시 본문의 사고 흐름, 소제목, 표/FAQ/체크리스트 사용 여부는 주제마다 자유롭게 설계합니다.
