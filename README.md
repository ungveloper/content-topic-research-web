# content-topic-research-web

네이버 검색·NAVER 검색어트렌드·Google Trends·Search Console·뉴스·커뮤니티·공식자료에서 얻은 신호를 한곳에 모아, **검색량이 아니라 게시 가치**를 기준으로 콘텐츠 주제를 선별하는 Next.js 도구입니다.

## 핵심 원칙

- 네이버 검색 API: 키워드 생산기가 아니라 **사용자가 실제로 묻는 문제 탐지기**로 사용
- NAVER 검색어트렌드 / Google Trends: WHAT보다 **WHEN(수요·발행 시기)** 판단에 사용
- 네이버 뉴스: 기사 재작성보다 **변경 감지**에 사용
- Search Console: 내 사이트가 이미 노출되는 **실제 기회**를 우선 발견
- 카페·지식iN·커뮤니티: 사실 근거가 아니라 **불편·질문 표현** 탐색
- 공식기관·제조사 자료: **사실 검증**에 사용
- 같은 검색 의도는 한 페이지로 클러스터링
- 웹서핑한 내용을 직접 체험한 것처럼 쓰지 않음
- 자동 NAVER 조사 결과는 스크립트 점수로 최종 주제를 결정하지 않음

## NAVER API HUB 설정

이 프로젝트는 2026년 NAVER API HUB 기준으로 다음 Application API를 사용합니다.

- 검색어트렌드
- 뉴스
- 블로그
- 지식iN
- 카페
- 웹문서

NAVER Cloud Platform의 **NAVER API HUB > Application > 인증 정보**에서 Client ID와 Client Secret을 확인한 뒤 프로젝트 루트에 `.env.local`을 만듭니다.

```env
NAVER_API_HUB_CLIENT_ID=...
NAVER_API_HUB_CLIENT_SECRET=...
```

기존 NAVER Developers의 `X-Naver-Client-Id` / `X-Naver-Client-Secret` 방식이 아니라 NAVER API HUB의 다음 인증 헤더와 엔드포인트를 사용합니다.

- API 도메인: `https://naverapihub.apigw.ntruss.com`
- Client ID 헤더: `X-NCP-APIGW-API-KEY-ID`
- Client Secret 헤더: `X-NCP-APIGW-API-KEY`
- 검색: `/search/v1/*`
- 검색어트렌드: `/search-trend/v1/search`

> Client ID와 Client Secret은 브라우저 코드에 넣지 않습니다. Next.js Route Handler에서만 읽도록 구성되어 있습니다.

## NAVER 검색어트렌드 사용 방식

앱에서 최대 5개 키워드를 비교할 수 있습니다. API가 반환하는 `ratio` 값은 절대 검색량이 아니라 요청한 기간·검색어 집합 안에서 정규화된 상대 지수이므로, **주제 결정용 절대 검색량이 아니라 수요·계절성·발행 시기 신호**로만 사용합니다.

- 최근 90일: 주간 단위
- 최근 1년: 월간 단위
- 저장 시 최근 4개 구간의 평균 상대지수를 `trendScore`로 기록

## 원클릭 조사 + ChatGPT Pro 주제 심사

첫 화면의 **오늘의 자동 탐색 시작** 버튼은 키워드 입력 없이 NAVER API 조사 데이터를 수집합니다. 다만 앱이 최종 주제를 자동 결정하지는 않습니다.

1. 넓은 생활 영역을 출발점으로 NAVER 지식iN에서 실제 질문을 수집합니다.
2. 명백한 광고성·관계 고민·의료·법률·금융·전문 안전 주제와 최근 중복 주제를 코드에서 1차 제거합니다.
3. 남은 지식iN 문제마다 NAVER 검색어트렌드·카페·블로그·뉴스·웹문서를 추가 조회합니다.
4. 각 후보의 질문·스니펫·원문 URL·트렌드 시계열을 `ResearchEvidenceBundle` JSON으로 묶습니다.
5. 앱은 이 JSON 전체가 포함된 **ChatGPT Pro 주제 심사 프롬프트**를 자동으로 클립보드에 복사합니다.
6. 사용자가 ChatGPT Pro 새 대화에 붙여넣어 의미 기반 심사를 실행합니다.
7. ChatGPT Pro의 JSON 결과를 앱에 다시 붙여넣고 **선정 후보 불러오기**를 눌렀을 때만 주제 후보가 생성됩니다.

즉, 스크립트는 API 호출·정리·중복 제거·금지 분야 차단만 담당하고, 검색 의도·유입 가능성·포화도·근거 품질·고유성·직접 테스트 가치는 ChatGPT Pro가 전체 Evidence Bundle을 비교해 판단합니다. 앱은 OpenAI API를 자동 호출하지 않으며 사용자가 버튼과 복사/붙여넣기로 각 단계를 직접 제어합니다.

ChatGPT Pro 심사는 최대 3개만 `direct-test` 또는 `research-verification`으로 선정하도록 설계되어 있습니다. 데이터가 약하면 0개를 선정해도 정상이며, `hold`와 `exclude`는 후보 목록에 들어오지 않습니다.

최근 최종 프롬프트 사용 주제는 60일, Evidence Bundle로 이미 검토한 주제는 14일 동안 유사 주제 재노출을 줄이기 위해 별도 로컬 기록에 보관합니다.

## 직접 테스트와 조사·검증 흐름

- `direct-test`: 안전하고 반복 가능하며 실제로 측정할 수 있는 주제만 선택합니다. ChatGPT Pro가 주제 특성에 맞는 N일 기간과 측정 항목을 설계합니다. 실제 수치·스크린샷·사진·시간·실패 기록이 없으면 최종 글 프롬프트를 만들지 않습니다. 매일 별도 글을 발행하지 않고 내부 기록을 모은 뒤 하나의 결과 포스트로 통합합니다.
- `research-verification`: 직접 테스트가 필요 없거나 적절하지 않지만 공식 원문 여러 개를 교차해 결정표·비교표·조건 분기 같은 고유 결과물을 만들 수 있을 때만 사용합니다.

의료·건강, 법률·분쟁, 금융·재정·세무·연금·보험·투자·대출, 감전·누전·가스·화재·구조물·전문 전기/가스 공사 등 고위험 주제는 API 수집 단계와 ChatGPT Pro 심사 프롬프트에서 이중으로 제외합니다.

## 2026-08 콘텐츠 품질 원칙

- 앱의 홈 카드(로고)를 누르면 작업 내용을 모두 초기화하고 `/`로 이동합니다. 입력값·리서치 신호·주제 후보가 있으면 브라우저 기본 확인창으로 작업 손실 가능성을 먼저 안내합니다.
- `오늘의 자동 탐색 시작`이 끝나면 주제 후보를 자동 확정하지 않고 ChatGPT Pro 주제 심사 패널로 이동합니다. 심사 JSON을 사용자가 다시 붙여넣고 `선정 후보 불러오기`를 눌렀을 때만 후보 큐로 이동합니다.
- ChatGPT 출력은 `auto-publisher-web`이 읽는 간결한 3개 섹션 규격(`# 1. 게시용 본문`, `# 2. 대표 이미지 생성 프롬프트`, `# 3. Rank Math SEO 패키지`)을 사용합니다. 게시용 본문은 `<!-- 게시용 본문 시작 -->` / `<!-- 게시용 본문 끝 -->` 사이에 두고, 첫 H1은 Auto Publisher가 제목으로 추출한 뒤 실제 WordPress 본문에서는 제거합니다. 게시 판단·고유 결과물·판단 흐름·1차 출처 검증·자체 검수는 프롬프트 내부에서 수행하되 별도의 `게시 전 확인 자료` 섹션으로 출력하지 않습니다.

콘텐츠는 **형식을 일부 통일하되 사고방식까지 통일하지 않는 것**을 원칙으로 합니다. 동일한 서론·FAQ·결론·안전문구를 제목만 바꿔 반복하지 않고, 문제별로 실제로 필요한 판단 순서와 검증 경로를 새로 설계합니다.

사이트 콘셉트는 `생활 문제 해결 기록소 + 디지털 생활 도구`입니다. 직접 경험 자료가 있으면 사진·스크린샷·사용 기간·비용·작업 시간·실패 사례 같은 증거를 우선 활용하고, 직접 경험이 없으면 체험담을 만들지 않습니다. 대신 제조사·공공기관 공식 문서 교차 비교, 조건별 결정표, 화면 경로 비교, 공개 사용자 사례의 반복 혼동 지점 분석처럼 **조사 자체를 고유 결과물**로 만듭니다.

발행 전에는 한국어 조사 오류, 중복 단어, 자동 조합형 문장, 다른 글에도 그대로 붙일 수 있는 공통 문단, 근거 없는 전문가·검수 표현, 충돌하는 날짜를 전수 점검하도록 프롬프트에 강제합니다.


## Auto Publisher 연동 규칙

ChatGPT 최종 결과의 **전달 규격은 고정**하지만 실제 게시 본문을 템플릿화하지 않습니다.

- 고정되는 것: `# 1. 게시용 본문`, `# 2. 대표 이미지 생성 프롬프트`, `# 3. Rank Math SEO 패키지`, 본문 시작/끝 주석, Rank Math 필드명
- 내부에서만 검증하는 것: 게시 판단, 고유 결과물, 주제별 판단 흐름, 실제 1차 출처, 중복/YMYL/문장 품질 검수
- 최종 출력하지 않는 것: `게시 전 확인 자료`, 백엔드용 검수표, 내부링크 후보, 조사 메모
- 자유롭게 달라져야 하는 것: 문제 정의, 판단 순서, H2/H3 구성, 비교표/체크리스트/FAQ 사용 여부, 결론 방식, 문장 리듬
- 모든 글에 `서론 → 원인 → 해결법 → FAQ → 결론` 같은 공통 구조를 강제하지 않습니다.
- 출력 전체를 복사해 `auto-publisher-web`에 붙여넣으면 제목·본문·대표 이미지 ALT·Rank Math 메타데이터가 추출되도록 맞춥니다.

즉, **컨테이너는 표준화하고 콘텐츠의 사고방식은 표준화하지 않는 것**이 원칙입니다.

## 고정 카테고리 정책

자동 발행에서 띄어쓰기나 표현 차이로 WordPress 카테고리가 계속 늘어나는 것을 막기 위해 최종 ChatGPT 출력의 `카테고리명`은 다음 5개 중 하나만 사용합니다.

- 집 관리
- 디지털 생활
- 생활 행정
- 정리·보관
- 제품 사용

계절, 브랜드, 제품명, 세부 증상은 카테고리를 새로 만들지 않고 태그로 표현합니다. 글의 전달 포맷과 taxonomy는 고정하지만 실제 게시 본문의 사고 흐름, 소제목, 표/FAQ/체크리스트 사용 여부는 주제마다 자유롭게 설계합니다.

## 후보 큐 노출 정책

NAVER 자동 조사 결과 자체는 곧바로 후보 큐에 들어가지 않습니다. ChatGPT Pro 심사 JSON에서 `direct-test` 또는 `research-verification`으로 선정된 항목만 후보 큐로 가져옵니다. 수동으로 만든 기존 후보에만 0~5 보조 점수표를 참고하며, ChatGPT Pro 선정 후보는 숫자 공식보다 심사 rationale과 high/medium/low 평가를 우선 표시합니다.

조사·검증형 후보는 최종 ChatGPT 글 프롬프트를 복사하면 `used-topics`에 기록되고 후보 목록에서 숨겨집니다. 직접 테스트형 후보는 테스트 계획을 먼저 복사해도 유지되며, 실제 증거를 입력한 뒤 최종 글 프롬프트를 복사했을 때만 60일 사용 기록에 남고 숨겨집니다.

## Evidence Bundle 설계

후보당 JSON에는 다음 데이터가 들어갑니다.

- 지식iN 대표 질문과 원문 URL
- NAVER 검색어트렌드 최근 90일 주간 상대지수 시계열
- 카페 반복 불편 사례
- 블로그 기존 답변·표현·포화도 참고 자료
- 뉴스 최근 변경 감지 자료
- 웹문서 공식 근거 후보와 `officialCandidate` 표시

`officialCandidate=true`는 URL 도메인을 기반으로 한 1차 표식일 뿐 최종 사실 판정이 아닙니다. ChatGPT Pro와 최종 원고 단계에서 실제 공식 원문인지 다시 확인하도록 프롬프트에 명시합니다.

## AdSense·콘텐츠 품질 방향

이 도구는 AdSense 승인을 보장하지 않습니다. 목표는 AI 사용을 숨기는 것이 아니라 **AI 대량생산형 사이트와 다른 제작 과정**을 만드는 것입니다. 많은 후보를 자동으로 글로 바꾸지 않고, 실제 질문 → 다중 출처 데이터 → ChatGPT Pro 심사 → 직접 테스트/공식 검증 → 실제 증거 → 하나의 고유 페이지 순서로 발행량을 의도적으로 제한합니다.

같은 검색 의도의 키워드 변형 글, 공통 서론/FAQ/결론 재사용, 분량 채우기, 뉴스 재작성, 가짜 체험담을 금지하고, 가능한 경우 실제 측정 데이터와 실패 기록을 사이트만의 1차 자료로 축적합니다.
